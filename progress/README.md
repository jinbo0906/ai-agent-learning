# 进度与质量数据

```
progress/
├── review-queue.yml         间隔复习排期 + 错题（attest review 读写）
├── flagship-selection.yml   旗舰章选择（第 6 周执行，必须引用真实数据）
├── weekly/week-NN.md        周复盘（模板：attest/templates/retro.md）
└── board.html               本地看板（attest board 生成，不入库）
```

## 看板指标

**加粗的三项是原方案没有、但更能反映真实学习质量的指标。**

| 指标 | 定义 | 为什么看 |
| --- | --- | --- |
| 章节状态 | 10 章 draft / needs_work / done | 覆盖度 |
| 四维雷达 + 趋势 | 每章四维分数 | 找系统性短板 |
| **校准误差** | `mean(\|自评 − Judge评\|)` 及趋势 | **你知不知道自己会不会**。<5 良好，5–12 正常，>12 说明系统性高估或低估自己。应随周次下降 |
| **保持率** | D+7 / D+21 得分 ÷ 首评得分 | ≥0.9 良好；0.75–0.89 安排复习；<0.75 回补学队列 |
| **证据密度** | 文章中可定位引用数 ÷ 核心主张数 | 是否真拿数据说话 |
| 复现率 | `attest check` 一次通过的章节比例 | 工程严谨度 |
| 返工轮数 | needs_work → done 的平均轮数 | 下降说明质量前置了 |
| 累计成本 | token 与费用 | 预算感（全书目标 <60 元） |

## 明确不采纳的指标

commit 数、代码行数、在线时长、阅读进度百分比。

这些容易被优化，却不能可靠代表学习质量 —— 读了不等于会了，
状态应由**证据齐套度**决定，不由投入量决定。

## 完成级别

| 级别 | 条件 |
| --- | --- |
| 🥉 铜 | 十章证据齐套，≥8 章 done，平均分 ≥75 |
| 🥈 银 | 十章全部 done，平均分 ≥80，十篇文章过发布门，Attest 到 v2 |
| 🥇 金 | 银 + 3 个旗舰实验 + Attest 到 v3 + 总复盘 + D+21 保持率 ≥0.8 |

**旗舰实验和 Attest v3 是加分项，不是硬门。**
第 7 章卡住（很可能，它需要 GPU）不会导致整个 18 周判定为失败 ——
你仍然能拿到银牌，并且清楚地知道差在哪。

这是与原方案的一处重要差异：原方案"任何硬门失败都不能被高分抵消"，
在单人自学场景下会制造中途放弃点，而不是激励完成。
