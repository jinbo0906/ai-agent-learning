# Attest —— 证据驱动的学习监督系统

> **它同时是两样东西**：
> 1. 监督这次十章学习质量的工具；
> 2. **这次学习的综合 Demo** —— 用书里的技术建的，每学完一章就把该章能力装进它。
>
> 这个合并是本方案与原方案最大的结构性差异。原方案把「监督系统」和「综合 Demo」
> 分成两个东西做，功能高度重叠、重复工程。合并之后：
> **一个你自己每天用的工具，好不好用你骗不了自己。**

---

## 为什么是本地 CLI，不是 GitHub Actions

| | 本地 CLI | GitHub Actions |
| --- | --- | --- |
| 反馈延迟 | **< 2 秒**（确定性检查） | 3–8 分钟（排队 + 冷启动 + 装依赖） |
| 答辩一轮 | 终端里一次对话 | 2 次 push + 2 次等 CI + 手工搬运哈希 |
| 隐私 | 笔记私有，可以诚实写"我不懂" | 公开仓库 = 低分与错误认知永久公开 |
| 可测试 | 普通 Python 包，pytest 直接跑 | 逻辑锁死在 workflow YAML |
| 可产品化 | 换外壳即可（Web / 桌面 / 小程序） | 目标用户被压缩到"会配 Actions 的开发者" |

**结论：Git 是账本，不是流水线。** 证据用 Git 版本化（diff 就是认知变化，天然防篡改），
但运行时必须在本地。CI 只做可选的周回归和看板构建，挂了不影响学习。

## 三个可泛化抽象

产品化程度取决于内核是否与"AI Agent Book"无关。三个抽象都无关：

```
attest/curriculum.yml          ① 课程规格 —— 换一本书只换这个文件
attest/rubrics/*.yml           ② 评分卡   —— 与学科无关，可复用可分享
evidence/chNN/                 ③ 证据包   —— 目录约定，与内容无关
```

引擎的六步 `start → check → quiz → grade → defend → review` 同样与内容无关。
换一门课 = 写一份 `curriculum.yml` + 选一张 rubric。

## 三层评估

```
第 1 层  确定性检查        本地 · <2 秒 · 零成本 · 随时可跑
         ├─ 六类产出齐套、必需 H2 非空、无占位符
         ├─ 证据索引的 path/location 可解析
         ├─ 报告数字能在 summary.json 中定位        ← 防"只跑通不分析"
         ├─ reproduce 命令可执行、产物一致           ← 第 5 章能力
         └─ 密钥扫描                                 ← 唯一有真实安全价值的检查
         失败 → 直接 needs_work，**不调用 LLM**（明确且省钱）

第 2 层  语义评分          本地调 API · ~30 秒 · ~0.3 元/章
         四维打分 + 逐条理由 + 证据引用 + 与自评的差值（校准误差）

第 3 层  个性化答辩        终端对话 · ~10 分钟 · 你在场
         2 个锚定你**具体主张 / 代码选择 / 实验数字**的追问
         能不看提交就回答的问题 = 无效问题
```

第 1 层零成本可重复，是这套设计的关键：你会在**写作过程中**反复用它，
而不是写完才发现结构不对。

## 威胁模型：为什么没有签名和哈希绑定

安全机制按**真实**威胁配置，不按想象中的威胁配置。

| 失效模式 | 概率 | 本系统的对策 |
| --- | --- | --- |
| **T1 AI 代写笔记与文章** | **极高** | 个性化答辩 + 语音作答（v3+voice）+ 必须引用自己实验的具体数字 + D+21 复述 |
| **T2 实验只跑通不分析** | 高 | `check_numbers_grounded`：报告数字必须能在 summary.json 定位 |
| **T3 学完就忘** | 高 | D+2 / D+7 / D+21 + 保持率 |
| **T4 自欺（自评过高）** | 中高 | **校准误差** = mean(\|自评 − Judge评\|)，并看它的趋势 |
| T6 篡改分数文件 | **≈ 0** | Git 历史（免费）。你是唯一用户，为防自己作弊而上 Ed25519 是负收益 |
| T7 学习者代码攻击评估系统 | **≈ 0** | 代码是你自己写的 |

省下的工程量全部投到 T1 和 T4 —— 尤其 **T4「校准误差」是原方案完全缺失的**：
它衡量"你知不知道自己会不会"，元认知准确度比分数本身更能预测长期效果。

## 版本路线：跟着学习进度长出来

**不要提前实现。** 每一章学完才知道这一步该怎么建 —— 这正是"学会了没有"的检验。

| 版本 | 时点 | 内容 | 用上的章节 |
| --- | --- | --- | --- |
| **v0** | ch1 后 | Agent 循环骨架：读证据（工具）→ 调 LLM 判分（模型）→ 写结果（工具）；终止条件、重试、预算 | 第 1 章 Harness |
| **v0.5** | ch2 后 | 分层上下文：稳定前缀（rubric + 课程规格）+ 动态部分（本章证据）；实测缓存命中的成本下降 | 第 2 章 KV Cache |
| **v1** | ch3 后 | 证据检索：书稿 + 十章笔记建索引，Judge 打分必须引用原文位置 | 第 3 章 混合检索 + 重排 |
| **v1.5** | ch4 后 | 工具化：check/quiz/grade/defend 变成工具 + 主动发现；**用自己的系统做本章实验** | 第 4 章 工具设计 |
| **v2** | ch5 后 | 复现检查器：沙箱内执行 reproduce、跑测试、比对 summary.json | 第 5 章 生成—执行—验证 |
| **v2.5** ★ | ch6 后 | **Judge 校准** —— 用前五章历史评分建校准集，测自洽性 / 位置偏差 / 长度偏差。**系统从玩具变可信** | 第 6 章 评估方法论 |
| **v2.8** | ch7 后（可选） | 小模型预筛：0.5B 判"是否占位 / 空泛"，大模型只处理通过预筛的 | 第 7 章 能力载体选择 |
| **v3** | ch8 后 | 自我进化闭环：从历史评分自动提 rubric/prompt 改进 → 校准集验证 → 发布或回滚；可信根不可自动修改 | 第 8 章 持续进化 |
| **v3+voice** | ch9 后（可选） | 语音答辩：口头讲解 → ASR → 评分。更快、更难代写 | 第 9 章 流式语音 |
| **v3+panel** | ch10 后（可选） | 多 Judge 仲裁 vs 单 Judge 三次取均值，**等 token 预算**下比谁更接近人工评分 | 第 10 章 等预算对照 |

> **v2.5 是全书最关键的一次集成**：在此之前你没有任何理由相信 Judge 给的分数。

`llm.py` 刻意做得很薄：**它没有任何评分逻辑**。Judge 怎么设计（prompt 组装、
rubric 应用、证据引用、追问生成）是第 1/2/6 章的学习内容。给你这一层，
只是因为写 HTTP 客户端没有学习价值，不该占用你的 7.5 小时。

```python
from attest.llm import chat
r = chat([{"role": "user", "content": "..."}], tag="grade:ch01", json_mode=True)
result = r.json()                      # 自动剥 ```json 围栏并解析
r.cost_cny, r.latency_s, r.prompt_tokens
```

失败抛 `LLMError`（基础设施错误 —— 你的 `grade` 应捕获它并只写 `last_error`，
不动分数），超预算抛 `BudgetExceeded`。

各命令的设计 brief（输入输出、代码量、验收标准）见
[使用指南 §4.3](../docs/使用指南.md)。

### Day 3 任务

`check.py::check_numbers_grounded` 目前返回 WARN。它是整层确定性检查里最有价值的一条 ——
让"报告里的数字"和"真实运行结果"不可能脱节。

测试已经写好，跑 `make test` 让它变绿：

```bash
python -m pytest attest/tests -v
```

四个设计决定（比代码本身更重要）：
1. 哪些数字要查？序号、年份、表格分隔线里的数字应排除
2. 容差多少？`12.3%` / `0.123` / `12.30` 应视为同一个数
3. summary.json 是嵌套的，要递归收集所有叶子数值
4. 报错要指出**哪一行的哪个数字**对不上，而不是只说"失败"

## 成本

| 项 | 每章 | 全书 |
| --- | ---: | ---: |
| 出题 / 评分 / 答辩 / 复习 / 重评 | ~8 次调用 | **~90 次** |

用 GLM / Kimi / DeepSeek，**全书总成本约 20–60 元人民币**。
预算护栏就是 `.env` 里一个 `ATTEST_BUDGET_CNY`，超了打印警告并停止调用 —— 20 行代码。
（原方案为控制这笔钱设计了原子预算账本、跨章共享预算、内容哈希缓存……投入产出比是负的。）
