## 这个仓库在做什么

**问题**：读完一本书，很难证明自己真的学会了。笔记会变成摘要，代码只是"跑通了"，
章节测试只考记忆，几周后什么都不剩。用 AI 辅助之后，产出质量和真实理解更是彻底混在一起。

**做法**：把学习过程改造成一条证据流水线。每章产出六类证据，由一个本地工具自动检查、
评分、追问、排期复习：

```
①定标 ──→ ②学做 ──→ ③表达 ──→ ④验收 ──────→ ⑤沉淀
 目标      跑基线     实验报告    确定性检查      间隔复习
 必答问题  改一个变量  逐章文章    四维评分        装进 Attest
 实验要求  记录指标               个性化答辩
                                  ↑
                        这一步防的是"AI 代写"
```

**关键设计**：这个监督工具（`attest`）**本身就是用这本书的技术建的**，
每学完一章就把该章能力装进它。它既是监督系统，也是这次学习的综合 Demo。

> 一个你自己每天用的工具，好不好用你骗不了自己。

## 快速开始

```bash
# 1. 安装（一次）
pip install -e ./attest[dev]
cp .env.example .env        # 填 API Key；.env 已在 .gitignore

# 2. 开始第 1 章
make start CH=1             # 打印本章目标 / 必答问题 / 实验要求，生成证据包
make snapshot CH=1          # 把 chapter1/context 快照到 evidence/ch01/lab/src/

# 3. 学习过程中随时（< 2 秒，零成本）
make check CH=1             # 结构、占位符、证据可定位、密钥扫描
python -m attest ping       # 验证 LLM 端点可用

# 4. 全书总览
make status
```

无 `make` 时用等价命令：`python -m attest start 1` / `snapshot 1` / `check 1` / `status`。

> 本仓库默认放在 `ai-agent-book/` 内（`attest/curriculum.yml` 的 `meta.book_repo: ".."` 指向书稿与配套实验）。
> 放到别处时改这一个字段即可。

### 前三天

**不要先建系统。先完整跑一遍第 1 章，再把手工做的事自动化**——这样每行代码都有明确用途。

| | 内容 | 时长 |
| --- | --- | ---: |
| **Day 1** | `python -m attest ping` 确认 LLM 可用 → `make start CH=1` → 跑通 `chapter1/context` 的一个 task | 2h |
| **Day 2** | 通读第 1 章（18,911 字 ≈ 47 分钟）→ 精读 + 概念图 + 回答 5 个必答问题 → **先自评四维分数** | 3h |
| **Day 3** | 跑三组上下文消融 → 写 `report.md` → **实现 `check_numbers_grounded`**（测试已写好，`make test` 让它变绿） | 3h |

到第 3 天结束你会有：一章真实证据 + 一个真在用的工具 + 对"这套流程哪里别扭"的第一手判断。
后面所有系统设计都基于这个判断，而不是规范文档的想象。

## 三处实验修正

原方案的默认实验与仓库实际代码存在事实冲突，已逐一核对 README 并修正。
修正内容直接写进了对应章节的 `report.md`，学习时不会踩坑。

| | 章 | 冲突 | 处理 |
| --- | ---: | --- | --- |
| **A** | 7 | 强制默认基线 `continued-pretraining` 实为 **Mistral-7B + 24GB 显存**，与"0.6B–1.5B 小模型"自相矛盾 | 按算力三选一（≥24GB / 8–16GB 或云 / 无 GPU），**硬要求不变**：真实前向反向参数更新 + 训练前后同一评估 + 目标集与保留集 |
| **B** | 6 | 要求 ≥20 任务，`public-health-reporting-eval` README 明确只有 **5 个** | 把"扩到 20 个并做难度分层"作为本章核心实验，单独预留 2 小时。扩展后的任务集也是 Attest v2.5 校准集的来源 |
| **C** | 9 | `streaming-speech` 需 **OpenAI 直连 Key**（whisper-1/tts-1），OpenRouter 无音频端点无法回退 | 决策树三选一。无 Key 时改造 ASR 后端为国内服务 —— **这个改造本身就是更好的实验证据** |

## 评估与门控

### 三层评估

| 层 | 内容 | 耗时 | 成本 |
| --- | --- | --- | --- |
| **1 · 确定性检查** | 结构、占位符、证据可定位、报告数字 vs `summary.json`、复现命令、密钥扫描 | **<2 秒** | 0 |
| **2 · 语义评分** | 四维打分 + 理由 + 证据引用 + **校准误差** | ~30 秒 | ~0.3 元 |
| **3 · 个性化答辩** | 2 个锚定你**具体主张 / 代码 / 数字**的追问，终端作答 | ~10 分钟 | ~0.1 元 |

第 1 层失败就直接 `needs_work`，**不调用 LLM**——既明确又省钱。
它零成本可重复，所以你会在**写作过程中**反复用它，而不是写完才发现结构不对。

### 四维评分与判定

概念 25 / 场景与代码 30 / 实验证据 25 / 费曼讲解与反思 20。

判定只有 3 条，按顺序：① 确定性检查失败 → `needs_work`；② 答辩未完成 → `needs_work`；
③ 总分 ≥80 且每维 ≥60% → `done`。基础设施错误（API 超时等）不写分数，保留上次有效结果。

| 级别 | 条件 |
| --- | --- |
| 🥉 铜 | 十章齐套，≥8 章 done，平均 ≥75 |
| 🥈 银 | 十章 done，平均 ≥80，十篇文章过发布门，Attest 到 v2 |
| 🥇 金 | 银 + 3 旗舰 + v3 + 总复盘 + D+21 保持率 ≥0.8 |

**旗舰和 v3 是加分项，不是硬门**——第 7 章卡住不会让整个 18 周判定失败。

## 几个关键决定

### 为什么本地优先，不用 GitHub Actions

| | 本地 CLI | GitHub Actions |
| --- | --- | --- |
| 反馈延迟 | **<2 秒** | 3–8 分钟（排队 + 冷启动 + 装依赖） |
| 答辩一轮 | 终端里一次对话 | 2 次 push + 2 次等 CI + 手工搬运哈希 |
| 隐私 | 笔记私有，**可以诚实写"我不懂"** | 公开仓库 = 低分与错误认知永久公开 |
| 可产品化 | 换外壳即可 | 目标用户压缩到"会配 Actions 的开发者" |

**Git 是账本，不是流水线。** 证据用 Git 版本化（`git diff` 就是认知变化，防篡改是免费副作用），
但运行时必须在本地。CI 只做可选的周回归，挂了不影响学习。

### 为什么没有签名和哈希绑定

安全机制按**真实**威胁配置。真正的风险是 **AI 代写**（极高概率）和**学完就忘**（高概率），
而不是"篡改分数文件"——你是唯一用户，为防自己作弊上 Ed25519 是负收益，
而且签名对 AI 代写完全无效（AI 写的内容照样能被合法签名）。

省下的工程量投到两处：**答辩加强到 2 问 + 语音作答**，以及新增**校准误差**指标。

### 校准误差是什么

`mean(|自评 − Judge评|)`。每章在 `grade` **之前**先自评，记录差值与趋势。

它衡量的是"**你知不知道自己会不会**"。元认知准确度比分数本身更能预测长期学习效果，
而且几乎没有学习产品在测这个。<5 良好，5–12 正常，>12 说明系统性高估或低估自己。

## 成本

全书约 **90 次 LLM 调用**（出题 / 评分 / 答辩 / 复习 / 重评），
当前配置 DeepSeek-V3（腾讯 LKEAP），实测单次 ping 0.000026 元，**全书总成本预计远低于 60 元**。

预算护栏就是 `.env` 里一个 `ATTEST_BUDGET_CNY`，超了打印警告并停止——20 行代码。

---

## 明确不采纳的指标

commit 数、代码行数、在线时长、阅读进度百分比。

这些容易被优化，却不能可靠代表学习质量。**状态由证据齐套度决定，不由投入量决定。**
